A **sigil** is a prefix that changes how the orchestrator handles a file, directory or config key instead of merging it.

They can be applied to physical filenames inside a [Templates folder](../templates), or bound to injection keys mapped inside Docker `CONFIG_PATHS` ([Configuration Injection](../config)).

## Breakdown of Action Sigils

- **`!force:<name>`**
  - **Behavior:** Creates the file if it doesn't exist, and deep-merges it if it does.
- **`!replace:<name>`**
  - **Behavior:** Skips merging and overwrites the target completely. Use this when the result should be an exact copy of your file.

- **`!delete:<name>`**
  - **Behavior:** Deletes the target file or directory in `/data/runtime`, e.g. to remove old configs or data folders.

- **`<name>`**
  - **Behavior:** This is the default behavior when no sigil is present. It instructs the orchestrator to merge the target file if it exists, and do nothing if it doesn't.

### File Trees Example

If used inside a `templates` directory physically mapping to `runtime`:

**Template Source**

<Files className="mb-6">
  <Folder name="data" defaultOpen>
    <Folder name="templates" defaultOpen>
      <Folder name="some-folder" defaultOpen>
        <File name="config.yml" />
      </Folder>
      <File name="!replace:replace-this.yml" />
      <File name="!delete:delete-this.json" />
      <File name="!force:force-this.yml" />
      <File name="merge-this.json" />
    </Folder>
  </Folder>
</Files>

<div className="grid grid-cols-1 md:grid-cols-2 gap-4">
  <div>

    **Runtime (Before)**

    <Files>
      <Folder name="data" defaultOpen>
        <Folder name="runtime" defaultOpen>
          <Folder name="some-folder" defaultOpen>
            <Folder name="sessions" />
          </Folder>
          <File name="replace-this.yml" />
          <File name="delete-this.json" />
        </Folder>
      </Folder>
    </Files>

  </div>
  <div>

    **Runtime (After)**

    <Files>
      <Folder name="data" defaultOpen>
        <Folder name="runtime" defaultOpen>
          <Folder name="some-folder" defaultOpen>
            <Folder name="sessions" />
          </Folder>
          <File name="replace-this.yml" className="text-yellow-500" />
          <File name="force-this.yml" className="text-yellow-500" />
        </Folder>
      </Folder>
    </Files>

  </div>
</div>

<Callout title="Note" type="info">
  `some-folder/config.yml` has no sigil and doesn't exist in the runtime yet, so it is skipped.
  `replace-this.yml` is overwritten, `delete-this.json` is deleted and `force-this.yml` is created.
  `merge-this.json` doesn't exist in the runtime either, so it is skipped as well.
</Callout>

## Deep Merging Behavior

Keep in mind that unless you bypass it with `!replace:`, files that exist on both sides are merged according to their format.

To read explicitly how JSON, YAML, TOML, and Properties behave during this procedure, read the [Deep Merging](../merging) guide.
