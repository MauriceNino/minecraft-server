The image is meant to be run with Docker Compose.

## Minimal Setup

A `docker-compose.yml` deploying a basic Paper server looks like this:

```yaml
services:
  minecraft:
    image: ghcr.io/mauricenino/minecraft-server:latest
    environment:
      TYPE: PAPER
      VERSION: latest
      MEMORY: 2G
      ACCEPT_EULA: 'true'
      PLUGINS: |
        modrinth:luckperms@latest
        hangar:viaversion@latest
    volumes:
      - ./data:/data/runtime
    ports:
      - '25565:25565'
```

## Shutdown

On `docker stop`, the server gets a `SIGTERM` and saves its worlds before exiting.

<Callout title="Important" type="warn">
  Docker kills the container after 10 seconds by default, which is often not enough for larger worlds. A server that is
  killed while saving can lose chunks or player data. Raise the limit per service:
</Callout>

```yaml
services:
  minecraft:
    stop_grace_period: 2m
```

## Health Check

The image has a `HEALTHCHECK` that sends a Minecraft status ping to the server, so `docker ps` shows the container as
`healthy` once players can connect. You can run it manually with `docker exec <container> mc-orchestrator healthcheck`.

The address and port are read from the server's config (`server-ip` and `server-port`, or the proxy's bind address).
With `enable-status=false` the server doesn't answer status pings, so the check only tests that the port accepts
connections.

## Volumes & State

Inside the container, everything lives in `/data` (set by [`DATA_DIR`](../environment#logging--paths)).

- `/data/runtime`: Where the server runs: worlds, configs, plugins and `server-lock.json`. Mount it to persist data.
- `/data/templates`: Where you mount your [templates](../templates). It can be read-only (`:ro`).

Both are declared as volumes, so without a mount Docker creates an anonymous volume for them.

## Running as a Different User

The container runs as the `minecraft` user with UID `1000` and GID `1000`. To run it as another user, for example so the
files in `./data` belong to your own account, set `user:` to the numeric UID and GID:

```yaml
services:
  minecraft:
    user: '1001:1001'
    volumes:
      - ./data:/data/runtime
      - ./templates:/data/templates:ro
```

<Callout title="Important" type="warn">
  A directory you mount from the host must be writable by that UID and GID. Create it before the container starts,
  otherwise Docker creates it owned by `root`:
</Callout>

```bash
mkdir -p ./data
sudo chown -R 1001:1001 ./data
```

Templates are only read, so they only need to be readable by that user. Volumes Docker creates from the image, including
named volumes, are writable for any UID. The UID doesn't need to exist in the image.

## Image Flavors

We provide a variety of Docker image flavors to suit your needs, varying by Java version and distribution.

### Java Versions

- **Java 25** (Default)
- **Java 23** (not for Microsoft)
- **Java 21**
- **Java 17**, **Java 11** and **Java 8** (Temurin only), for older Minecraft versions

Minecraft 26.1 and newer need Java 25, 1.20.5 - 1.21.11 need Java 21, 1.18 - 1.20.4 need Java 17. Versions before 1.17
often don't run on anything newer than Java 17, and 1.12 and older need Java 8. The orchestrator prints a warning on
startup when the image's Java doesn't fit your `VERSION`.

### Java Distributions

You can choose from several popular Java distributions:

- **Temurin** (Default, via Eclipse Adoptium)
- **Corretto** (Amazon)
- **Microsoft**
- **Azul** (Zulu)
- **GraalVM** (Oracle)

### Tagging Scheme

Releases follow [Semantic Versioning](https://semver.org). A major version changes behavior in a way that can break your
setup (environment variables, volume layout, defaults), a minor version adds features, and a patch version fixes bugs.
The changes of each release are listed on the [releases page](https://github.com/MauriceNino/minecraft-server/releases).

Tags follow the pattern `<version>-java<version>-<distribution>`, with the distribution in lowercase (`temurin`,
`corretto`, `microsoft`, `azul`, `graalvm`). Leave out the Java part for Java 25 Temurin, and the release part to get
the newest release.

| Feature                           | Tag Example            |
| --------------------------------- | ---------------------- |
| Newest release (Java 25, Temurin) | `latest`               |
| Pinned release                    | `1.2.3`                |
| Newest `1.2.x` / `1.x` release    | `1.2` / `1`            |
| Specific Java version             | `java21-temurin`       |
| Pinned release, specific Java     | `1.2.3-java21-temurin` |
| Different distribution            | `java25-graalvm`       |

The image is published to the GitHub Container Registry (`ghcr.io/mauricenino/minecraft-server`) and to Docker Hub
(`mauricenino/minecraft-server`) with the same tags, for `linux/amd64` and `linux/arm64`.

Every commit on `main` is also published as `edge` (the newest one) and `sha-<commit>`, for Java 25 Temurin only. These
builds are untested outside of CI and can change at any time, so don't use them for a server you care about.

<Callout title="Hint" type="info">
  If you are unsure which one to use, `latest` (Java 25 Temurin) is recommended for most users. To only get updates that
  don't break anything, use the major version, e.g. `1`.
</Callout>
