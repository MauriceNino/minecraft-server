---
title: Variable Interpolation
description: Injecting environment variables into configuration files
---

The orchestrator supports dynamic variable interpolation across all configuration files handled during the
[Templates](../templates) and [Config Injection](../config) phases.

This allows you to keep sensitive credentials or dynamic values (like hostnames, ports, or API keys) out of your
template files and manage them entirely via Docker environment variables.

## Usage

During the preparation phase, the orchestrator automatically scans for environment variable placeholders formatted as
`$[VARIABLE_NAME]` in your payload files. These placeholders are directly interpolated and replaced with their actual
runtime environment variable values.

### Basic Example

If you have an environment variable `DB_PASSWORD=secret123` and a template file `config.yml`:

```yaml
database:
  password: $[DB_PASSWORD]
```

The resulting file in the runtime directory will be:

```yaml
database:
  password: secret123
```

## How it works

1. **Detection:** Before any merging occurs, the orchestrator reads the content of the template file or `CONFIG_<key>`
   variable.
2. **Replacement:** Every `$[NAME]` placeholder is replaced with the value of the environment variable `NAME`. Names may
   contain letters, digits and underscores and must not start with a digit.
3. **Pipeline:** The interpolated content is then [deep-merged](../merging) or written to the runtime directory.

If a variable isn't set, a warning is logged and the placeholder is left as it is. An empty variable is replaced with an
empty string.

<Callout title="Important" type="warn">
  Values are inserted as they are, without quoting or escaping: quote the placeholder in the file (e.g. `password:
  "$[DB_PASSWORD]"`) if the value may contain characters that are special in that format.
</Callout>

Binary files in templates are copied without interpolation.

<Callout type="info" title="Note on Secrets">
  Variable interpolation is the recommended way to handle secrets. By using `$[SECRET_KEY]`, you can safely check your
  templates into Git (GitOps) while keeping the actual sensitive values in a `.env` file next to your
  `docker-compose.yml`. Only environment variables are read, not Docker secret files.
</Callout>
